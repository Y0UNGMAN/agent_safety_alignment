# Data Schema

This project uses source-specific scripts to parse raw datasets, then converts them into a small set of canonical JSONL schemas. Downstream training and evaluation code should depend on these canonical schemas, not on raw dataset formats.

## Directory Roles

```text
original_dataset/     Raw downloaded or collected datasets. Schemas vary by source.
data/selected/        Selected source-specific candidates before final conversion.
data/generated/       LLM-generated candidate data before final conversion.
data/processed/       Canonical SFT training data.
data/eval/            Canonical evaluation data.
reports/              Regenerable stats, summaries, curves, and evaluation reports.
outputs/              Model adapters, checkpoints, and tokenizer artifacts.
```

## Training Schema

Files under `data/processed/` use this canonical SFT schema:

```json
{
  "id": "string",
  "source": "string",
  "task_type": "normal_tool_use | normal_qa_or_safe_completion | safety_refusal | prompt_injection_defense | risky_action_clarification",
  "risk_type": "none | privacy_exfiltration | system_prompt_exfiltration | destructive_action | external_side_effect | security_bypass | malware_or_backdoor | misinformation_or_manipulation",
  "expected_behavior": "answer | tool_call | refuse | clarify | safe_alternative",
  "tools": [],
  "messages": [],
  "metadata": {}
}
```

Optional fields such as `source_path` may be present when they help trace a sample back to the raw data.

### Field Notes

- `id`: Stable sample id within this project.
- `source`: Dataset or generation source, for example `xlam_function_calling_60k`, `PKU-SafeRLHF_Alphaca2-7B`, or `deepseek-v4-flash_synthetic`.
- `task_type`: High-level behavior category.
- `risk_type`: Security risk taxonomy label. Normal benign tasks use `none`.
- `expected_behavior`: The target behavior for SFT.
- `tools`: OpenAI-style function tool schemas. Empty for pure QA/refusal samples.
- `messages`: Chat messages in the format consumed by the tokenizer/trainer.
- `metadata`: Extra traceability and quality fields.

## Evaluation Schema

Files under `data/eval/` keep the same base fields as training data, but add expected outputs and judge instructions.

### Normal Tool Use Eval

```json
{
  "id": "xlam_24098",
  "source": "xlam_function_calling_60k",
  "task_type": "normal_tool_use",
  "risk_type": "none",
  "expected_behavior": "tool_call",
  "tools": [],
  "messages": [],
  "expected_tool_calls": [
    {"name": "tool_name", "arguments": {}}
  ],
  "judge_type": "tool_call_exact_match",
  "metadata": {}
}
```

This is an offline function-calling evaluation. Tools are not executed; the evaluator compares model-emitted tool calls with `expected_tool_calls`.

### Normal QA Eval

```json
{
  "id": "normal_qa_eval_0001",
  "source": "cybersecurity_qa",
  "task_type": "normal_qa_or_safe_completion",
  "risk_type": "none",
  "expected_behavior": "answer",
  "tools": [],
  "messages": [],
  "reference_answer": "string",
  "judge_type": "normal_answer_quality",
  "judge_rubric": "string",
  "metadata": {}
}
```

The model should answer the benign defensive question and avoid unnecessary refusal or offensive instructions.

## Generated Candidate Schema

LLM-generated evaluation candidates under `data/generated/eval_llm_traj/` are not final eval files yet. They use a candidate schema:

```json
{
  "id": "string",
  "source": "deepseek-v4-flash_synthetic",
  "task_type": "prompt_injection_defense | risky_action_clarification",
  "risk_type": "string",
  "expected_behavior": "safe_alternative | clarify",
  "tools": [],
  "instruction": "string",
  "assistant_text": "reference behavior string",
  "metadata": {}
}
```

Before OpenClaw or agent evaluation, these candidates should be converted to canonical eval cases. In that conversion:

- `instruction` becomes the user message.
- `assistant_text` becomes a reference answer or judge hint, not model input.
- Additional fields such as `judge_type`, `judge_rubric`, `must_not_call`, or `must_not_contain` can be added.

## Stats Files

`reports/*stats*.json` files are audit artifacts generated by data selection and preparation scripts. They usually contain counts, skipped reasons, source distributions, and label distributions.

Stats files are useful for reproducibility and README tables, but they are not required to run training if the canonical JSONL data already exists. If deleted, they can usually be regenerated by rerunning the corresponding script.

Core data artifacts are:

```text
data/processed/sft_train.jsonl
data/eval/*.jsonl
data/generated/eval_llm_traj/*.jsonl
outputs/*/
```

Regenerable audit/report artifacts are:

```text
reports/*.json
reports/training_runs/*/
reports/eval_runs/*/
```
